# Phase 3 진입 판정

판정: **NO-GO**.

다중 로봇은 스폰하지 않았고 주행하지 않았다. 아래는 단일 로봇 로그와 기존 런치 조사를 기준으로 한 판정이다.

## 조건

| 조건 | 충족 |
| --- | --- |
| 단일 로봇 Gazebo E2E가 로그로 확인됨 | 부분. 오버레이 이후 12회 중 11회가 0.25 m 안 `COMPLETED`다. 좌표 `(-0.6, -0.4)`는 Nav2 abort, FMS `FAILED` |
| 0.25 m 불일치의 원인과 수정 효과가 설명됨 | 충족. 원인 문서. 같은 5좌표 중 4좌표는 0.109–0.177 m로 완료. 5번째의 거짓 `SUCCEEDED`는 abort로 바뀌었다 |
| 반복 주행이 안정성 기준을 충족 | 미충족. 요청한 재실행 좌표에 실패가 남아 있다. 12회는 운영 신뢰성이 아니다 |
| UUID와 task 상태 일치 | 충족. 채점 12회와 회귀의 취소·abort·kill·재시작·lease에서 UUID가 유지됐다 |
| 세션, lease, epoch 회귀 | 충족. `docs/phase2-2-1-regression-results.md` |
| Mock과 물리 제어 차단 | 충족. 물리 등록 403, cmd_vel 404, mock-observe 403 |
| 다중 로봇 namespace, TF, Nav2 action 분리 설계 | 미충족. 조사만 되어 있고 실행 설계가 끝나지 않았다 |

실패가 남아 Phase 3 주행은 보류한다. 열린 공간 7/7 완료만으로 GO를 만들지 않는다.

## 미검증

- 네트워크만 끊어지는 경우. NOT_RUN
- 강제 DB 쓰기 실패. NOT_RUN
- `(-0.6, -0.4)`를 0.25 m 안에 세우는 제어. 하지 않았다. tolerance를 늘리면 다시 대체 점 성공이 될 수 있어 늘리지 않았다
- 플래너 snap 0.15 m와 checker 0.12 m가 같은 방향으로 겹칠 때의 0.27 m. 이번 표본에서는 `COMPLETED`로 나타나지 않았다
- Nav2 재시작 직후 goal status가 없어 첫 전송이 거절되는 동작. 점수 외 취소 1회로 status를 만든 뒤 주행했다. 에이전트의 fail-closed는 그대로다
- 로봇 3대 동시 주행. 하지 않음

## 다중 로봇 준비

`docs/phase3-readiness.md`의 조사를 유지한다. 이번 단계에서 추가한 실행은 없다.

| 항목 | 준비 |
| --- | --- |
| Robot id와 ROS namespace | 미완. `pinky-sim`은 하이픈 때문에 ROS 이름이 아니다 |
| 로봇별 Nav2 action | 미완. `/navigate_to_pose` 하나. 클라이언트에 로봇별 이름이 없다 |
| TF 접두사 | 미완. `map` → `base_footprint` 하나 |
| odom과 센서 토픽 | 미완. 브리지 토픽이 전역이다 |
| 중앙 스케줄러 | 단일 로봇에서 동작. 로봇별 격리는 실측하지 않음 |
| 로봇별 세션 | 한 로봇의 두 번째 세션은 409. 로봇 간 세션은 실측하지 않음 |
| 다른 로봇 goal 차단 | 설계만 필요. 구현·실측 없음 |
| 공용 구역 예약 | `zones.json`은 공장 맵과 다른 12 m × 8 m 바닥이다. 두 로봇 충돌은 NOT_RUN |

## 판정 근거

거짓 완료는 줄었다. 빈 칸 목표와 `(-0.8, 0.2)`는 FMS 0.25 m 안으로 끝났다. `(-0.6, -0.4)`는 완료되지 않았고, 다중 로봇을 나누는 실행 설계도 없다. 두 조건이 열려 있으므로 지금은 로봇을 더 올리지 않는다.
